# 问题清单

所有问题统一记在这里，由巡逻机器人（`npm run patrol`）、场景体检（`npm run audit:scene`）、截图巡检（`npm run shots`）和人工审阅产生。

## 约定
- **分类**：程序缺陷（逻辑、物理、碰撞、数据错误）/ 视觉缺陷（画面上能看出来的错误）/ 审美建议（不算错，但可以更好；只记录，不自动改）。
- **严重度**：高（崩溃、卡死、主线功能不可用）、中（明显影响体验，但有绕行办法）、低（小瑕疵）。
- **状态**：待修、修复中、已修复（注明提交）、暂缓（注明原因）、无需处理（设计如此或误报）。
- **编号**：程序缺陷 `P-xxx`，视觉缺陷 `V-xxx`，审美建议 `A-xxx`。编号只增不复用。
- **签名**：工具输出的问题带签名（如 `穿墙|315,-115`）。已登记的问题签名写进 `tests/known_issues.json` 并注明编号，`--strict` 门禁只会拦截新出现的问题。修复后要从 `known_issues.json` 删除对应签名，工具会提示"已登记但本轮未再出现"的条目。
- 每条问题都要有：位置坐标、复现步骤（或工具签名与复现命令）、来源，能判断的附上原因。

## 程序缺陷

### P-001 陡坡上的礁石会把人"吞"进去　【中｜已修复】
- **位置**：(314.6, -113.3) 东海岸崖壁礁石 r=1.93；(186.7, 185.7) 南岸礁石 r=1.34。
- **复现**：`python3 tests/patrol.py --seed=7 --repro=walk-12`；水中那处用 `--repro=swim-05`。
- **现象**：人物中心嵌进礁石的圆柱碰撞体，四周迈不出去，1.2 秒后卡住保护把人传送回起点。
- **原因**：`src/11_fp.js` 的移动循环中，`pushOut` 算出的推出点要再过一遍 `canStep`。礁石长在陡坡上，推出点的坡度超过可攀爬上限，这次推出就被拒绝，人留在碰撞体里。
- **修复**：推出点不可达时退回本步起点，人不会再迈进实心体（`src/11_fp.js` 移动循环）。回归：`tests/regression.py` 严格重放上述两个计划。

### P-002 潜到最深处朝岸游，会嵌进海底斜坡　【低｜已修复】
- **位置**：(-272.4, -149.5)、(184.6, 187.4)、(141, -199) 等水下斜坡，嵌入 0.3～1.2 m。
- **复现**：`python3 tests/patrol.py --seed=20260923 --repro=swim-06`。
- **原因**：游泳时 `canStep` 只检查新位置的水底是否低于水面 +1.1，不检查水底是否高于当前脚底。下潜目标深度虽然每帧重算，但上浮速度（1.6 m/s）赶不上斜坡抬升。
- **修复**：游泳状态下脚底不低于当前位置的水底（`src/11_fp.js` 竖向状态机）。回归：`tests/regression.py`。

### P-012 在 Claude 网页预览中打开，岛上漫游报错并卡死　【高｜已修复】
- **现象**：预览页面禁止创建后台线程，控制台先出现“后台生成不可用，回退主线程”，进入漫游并传送到有草地的地方（如沙滩）后报 `Cannot read properties of undefined (reading 'NaN')`，主循环随之停止，之后点传送没有任何反应。下载到本地运行时后台线程可用，不报错。
- **复现**：`#q=high,debug,noworker` 强制主线程生成，进入漫游传送到 (0, 20)。只在高、中档出现（低档不生成近景草叶）。
- **原因**：主线程回退路径 `generateIsland` 的 `onMain()`（`src/00_gen.js`）把地表贴图原样以 canvas 元素返回，而后台线程返回的是 `{data, w, h}` 像素数据。近景草叶取色 `colAt()`（`src/12_grass.js`）按像素数据读取 `gd.w`、`gd.data`，在 canvas 上都是 undefined，下标成了 NaN 并抛错；小地图底图同样读不到像素，回退时是空白的。
- **修复**：`onMain()` 与后台线程一样，把地表贴图和遮罩转成 `{data, w, h}` 再返回。回归：`tests/regression.py`（P-012 用例：无后台线程、高档画质、传送到沙滩后按 W 前进，要求不报错且位置改变）。

### P-013 湖岸泥色的判断符号反了，全岛地表底色都被涂成泥色　【高｜已修复】
- **现象**：港口沙滩是灰褐色，不是设计中的“碧海银沙”（审美建议 A-001 记录的就是这个）。草地、林地的地表底色也都是同一种褐色 (90, 84, 62)，只是被农田、道路、植被遮住了一部分。漫游时草地上没有近景草叶。
- **复现**：读取地表贴图像素，港口沙滩 (0, 25)、草地 (120, 40) 都是 (90, 84, 62)；草地周围的近景草叶为 0 丛。
- **原因**：`lakeSD()`（`src/03_terrain.js`）湖内为正、湖外为负，其他调用处都按这个约定写的。只有两处写反了：
  - `src/04_ground.js` 的湖岸泥色按“湖外为正”判断 `lk < 0.3`，湖外恒成立且权重为 1，全岛湖外的底色都被泥色 [92, 86, 64] 覆盖；
  - `src/04b_detail.js` 的材质权重图同样判断反了，湖外全岛都被设成“草 0、沙 0.5、土 0.5”，近景草叶的生长条件（草权重 ≥ 0.7）在草地上从来不成立。
  - 两处都是最初上传的版本就有。
- **修复**：两处改为按“离湖岸外侧的距离 = -lakeSD”判断。修复后沙滩为银白细沙，草地恢复绿色，湖底仍是深色泥，漫游时草地上有近景草叶。回归：`tests/invariants.py` 检查沙滩、草地、湖底的地表色和草地上的草叶数量（修复前 5 条失败）。

### P-014 全岛植被共用一条随机数序列，局部地形改动会让全岛树木整体挪位　【低｜已修复】
- **现象**：2026-09-25 01:20（新加坡时间）为栈道削平岩石（`carveBoardwalk`）后，只改了东岸栈道两侧 4 m 的地形，别墅、宿舍楼、鸟瞰等 8 个视觉回归机位的远山树木都换了位置（差异像素 1～10%）。圆柱碰撞体多了 54 个（树与大块岩石）。
- **原因**：`src/08_vegetation.js` 的抖动网格撒点从头到尾共用一个 `mulberry32(4242)`，每个格点抽几次随机数取决于这个格点是否被接受（高度、法线、道路、排除区）。局部地形一变，被接受的格点变了，之后所有格点抽到的随机数都错位；后面给每棵树选树种、大小时也共用序列，同样整体错位。
- **本次处理**：接受这次重排，数量基线与视觉基线各单独提交并附对比图。
- **建议修复**：改为按格点坐标取随机数种子（每个格点独立），以后任何局部改动只影响附近的树。代价是全岛植被会一次性重新排布，需要你确认后再做。
- 2026-09-26 21:40（新加坡时间）机场道路绕行又触发一次重排（新路沿线清掉树木，圆柱碰撞体 4393 → 4372），同样按本条处理。
- **修复**（2026-09-26 21:55（新加坡时间），你已同意）：新增 `vegCell(x, z, salt)`，按格点/树/岩块自身坐标哈希出独立随机数；树与灌木撒点抽成纯函数 `vegScatter`；树种与大小、灌木、扶桑、蕨类、两处碎石撒点、岩块朝向各用不同的 salt，全岛不再共用序列。全岛植被一次性重排（数量基线、视觉基线单独提交并附对比图）。
- **回归**：`tests/regression.py` 用真实地形和“挖出半径 6 m 水坑”的地形各跑一次 `vegScatter`，12 m 以外的树与灌木必须完全相同。旧写法（共享序列）下该项失败：树、灌木都整体错位。

### P-015 湖里的溪蟹会爬到岸边水线以上的卵石上　【低｜已修复】
- **现象**：2026-09-25 04:40（新加坡时间）`npm run test:ecology` 偶发失败：“lake 有 1 个生物钻进水底或跑出水面，高度 10.44，地面 10.44 @ (183.1, -68.2)”（湖面 10.3）。
- **复现**：`#still` 模式下页面先按真实帧间隔跑 3 帧，随机游走状态每次不同，所以时有时无。确定性复现：检查溪蟹可选的窝，其中有岸边水线以上的卵石。
- **原因**：`src/17b_eco_lake.js` 的溪蟹在“大卵石”之间横行，大卵石取自整个卵石撒点，撒点范围包含岸边水线以上 0.3 m 的一圈，溪蟹选中这些卵石就会爬出水面。
- **修复**：溪蟹只把水深 ≥ 0.2 m 的大卵石当作窝。回归：`tests/ecology_test.py` 逐个检查溪蟹可选的窝都在水下（确定性，不依赖随机游走）。

### P-016 三个水域的生态共用一条随机数序列，改湖会让闸内港口、外海的布置整体错位　【低｜已修复】
- **现象**：2026-09-25 05:50（新加坡时间）把淡水湖改成水族馆式后，闸内港口礁盘、海草床在原机位上都看不见了（换到了别处）。
- **原因**：`ECO_R` 是全局唯一的随机数序列，湖、闸内港口、外海依次建造。湖里抽的随机数个数一变，后面两个水域的所有随机位置都错位（与 P-014 植被同类）。
- **修复**：`ecoSeed(n)` 在每个水域建造前用各自固定的种子重置（湖 1001、闸内港口 2002、外海 3003）。回归：`tests/ecology_test.py` 检查闸内港口、外海建造前都重置了种子。
- 本次重置后闸内港口、外海的布置与之前不同（一次性），以后改一个水域不会再影响另外两个。

### P-017 鲸群可能游进浅水甚至游上岸，被抬到地面以上　【中｜已修复】
- **现象**：2026-09-25 06:05（新加坡时间）`test:ecology` 报外海西南座头鲸出现在 (-205.3, 16.1, 172.4)——陆地上方 16 m。

- **原因**：`src/17d_eco_ocean.js` 的 `EcoPod` 只在挑选领头航点时检查水深；跟随者按编队位置追赶、以及两航点之间的直线都可能跨过海岸，最后一行 `y = max(y, 地面 + 2.5)` 又把游上岸的鲸抬到地面以上。
